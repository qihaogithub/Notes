## 前言：给运营设计师的切图指南

本文是为运营活动设计师准备的切图教程。你可能精通视觉效果，但对前端开发如何实现这些效果感到陌生。本教程的核心目标是：

1. **让你理解前端是如何“思考”和“实现”设计的。**
2. **建立一套清晰的“设计-切图-协作”规范。**
3. **掌握能提升开发效率和页面性能的专业技能。**

阅读后，你将能够产出**开发同学爱不释手的高质量切图**，让设计被 1:1 高效还原。让我们开始吧！

## 一、切图基础认知：什么东西该切，什么东西不该切？

### 必须切图的元素

- **复杂 Banner**：包含丰富光影、纹理、合成效果的头图
- **装饰性插画/海报**：手绘吉祥物、复杂场景图
- **特殊字体标题**：设计了变形、立体、金属质感等特效的艺术字标题
- **复杂交互控件**：包含渐变、高光、纹理等复杂视觉效果的按钮

### 不需要切图的元素

- **正文纯文字**：请直接用代码写。
- **简单色块/纯色背景**：一行 `background-color` 搞定。
- **标准几何图形**：如圆形、矩形，CSS 画得更快更轻。
- **简单渐变与阴影**：CSS 的 `linear-gradient` 和 `box-shadow` 效果足够且更灵活。

**💡 请时刻牢记这个核心原则：**  
**能用代码实现的，绝对不用图片。**  
**必须用图片的，也要让它又好又快。**
## 二、盒子模型：从“图层”到“盒子”的思维转换

这是理解切图的**核心**。设计师习惯图层，开发者习惯盒子。

**为了帮助你快速理解，我们可以做一个类比：**

|设计师的视角 (PS/Figma)|开发者的视角 (HTML/CSS)|
|:--|:--|
|一堆可以自由移动、叠加的**图层**|一堆有固定尺寸和位置的**矩形盒子**|
|关注视觉、效果、组合|关注宽度、高度、间距、层级|
|一个按钮可能是“背景层+文字层+阴影层”|一个按钮就是一个`<button>`标签构成的盒子，内部有文字|

![](https://qhdtc.oss-cn-chengdu.aliyuncs.com/obsidian/20251211164541247.png)

**盒子模型在切图中的关键应用：**

1. **精准控制切图范围**：我们切的应该是“盒子”里**无法用代码实现**的那部分“内容”，而不是整个带间距的盒子。
2. **切图边界的黄金法则**：切图内容紧贴边缘，不要留白（除非有弥散投影）。
3. **区分背景图和内容图**：背景图可以平铺拉伸，内容图要保持比例。

**🔎 快速检查：**  
在切图前，问自己：“我这个元素，哪些部分是可以用CSS代码画出来的？哪些部分是必须做成图片的？”  
把能用代码实现的部分标注出来，只切剩下的部分。

## 二、切图规范体系：从原理到实践

### 1. 格式选择：透明度与体积的平衡

| **格式**   | **适用场景**     | **核心优势**       | **原理说明**                                                                                   |
| ---------- | ---------------- | ------------------ | ---------------------------------------------------------------------------------------------- |
| **PNG-24** | 按钮、图标、浮层 | 支持透明通道       | 像一块「玻璃」，能让图片后面的背景透出来。透明角不会变成白色实心块。                           |
| **JPG**    | Banner、大背景图 | 高压缩率，体积小   | 像一张「照片」，压缩算法强大，适合色彩丰富的复杂图片，但不支持透明。                           |
| **SVG**    | 简单图标/Logo    | 矢量清晰，体积小   | 基于「数学公式」，存储点和线的坐标，无论放多大都清晰锐利，且文件体积极小。                     |
| **WebP**   | 所有图片类型     | 兼顾透明度与压缩率 | 新一代图片格式，结合了 PNG 的透明度和 JPG 的压缩率，体积比 JPG 小 30%-40%。                    |
| **AVIF**   | 高质量图片       | 极致压缩，更高质量 | 基于新一代视频压缩算法，体积比 WebP 小 20%-50%，但兼容性略低，适合对加载速度有极高要求的场景。 |

### 2. 尺寸与倍图：高清显示的秘密

#### 核心概念与底层原理

#### 显示技术底层原理

- **逻辑像素（CSS Pixel）**：网页布局中使用的抽象单位，与设备无关。它是一个抽象的测量单位，不直接对应屏幕上的物理像素点。

  - **底层机制**：浏览器会根据设备像素比 (DPR) 自动将逻辑像素转换为物理像素进行渲染
  - **计算公式**：物理像素 = 逻辑像素 × 设备像素比

- **物理像素（Device Pixel）**：设备屏幕实际的像素点，是屏幕硬件的最小显示单元。

  - **特性**：不同设备的物理像素密度差异很大，从普通屏的 72 PPI 到高端屏的 500+ PPI

- **设备像素比（DPR, Device Pixel Ratio）**：同一方向上，物理像素数量与逻辑像素数量的比值

  - **公式**：DPR = 物理像素宽度 / 逻辑像素宽度
  - **示例**：iPhone 15 Pro 的 DPR 为 3.0，意味着 1 个 CSS 像素会渲染为 3×3=9 个物理像素

- **Retina 屏**：DPR≥2 的高分辨率屏幕
  - **技术本质**：当人眼与屏幕距离约 30cm 时，若像素密度超过 300 PPI，人眼无法分辨单个像素点
  - **影响**：催生了「倍图」需求，确保图片在高分辨率屏幕上显示清晰

#### 设计稿尺寸对比与导出策略

目前主流的设计稿尺寸有两种：**375px 单倍稿**和**750px 二倍稿**。以下是两种尺寸的对比与导出策略：

| **设计稿类型** | **画布宽度** | **对应逻辑像素**       | **导出倍图策略**                               | **适用场景**                                 |
| -------------- | ------------ | ---------------------- | ---------------------------------------------- | -------------------------------------------- |
| **单倍稿**     | 375px        | 1:1 对应移动端逻辑像素 | @2x（导出时放大 200%）、@3x（导出时放大 300%） | 设计与前端协作紧密，前端直接使用逻辑像素布局 |
| **二倍稿**     | 750px        | 1:2 对应移动端逻辑像素 | @2x（导出时保持 100%）、@3x（导出时放大 150%） | 传统设计流程，设计师习惯使用高分辨率画布     |

**导出示例：**

- 单倍稿（375px）中 100px × 100px 的按钮 → 导出 @2x 为 200px × 200px，@3x 为 300px × 300px
- 二倍稿（750px）中 200px × 200px 的按钮 → 导出 @2x 为 200px × 200px，@3x 为 300px × 300px

#### 设备对应关系与 DPR 参考

| **DPR 值** | **典型设备**                                   | **建议使用**       |
| ---------- | ---------------------------------------------- | ------------------ |
| 1x         | 老款 Android 机型、部分低价手机                | @1x 图（极少使用） |
| 1.5x       | 部分 Android 机型                              | @2x 图（缩放显示） |
| 2x         | iPhone SE、iPhone 8、大部分 Android 中高端机型 | @2x 图（必须）     |
| 3x         | iPhone 12/13/14/15 系列、Android 旗舰机型      | @3x 图（推荐）     |
| 4x         | 部分折叠屏、高分辨率平板                       | @3x 图（缩放显示） |

#### 设计软件设置与导出技巧

**Figma/Sketch 设置：**

- **单倍稿（375px）**：画布宽度设置为 375px，导出时选择 2x 或 3x
- **二倍稿（750px）**：画布宽度设置为 750px，导出时选择 2x 或 3x
- **技巧**：使用「切片命名变量」自动生成带倍图标识的文件名（如 `button-primary@{scale}x.png`）

**Photoshop 设置：**

- **单倍稿（375px）**：72dpi，375px 宽度，导出时设置缩放比例为 200%（@2x）或 300%（@3x）
- **二倍稿（750px）**：72dpi，750px 宽度，导出时设置缩放比例为 100%（@2x）或 150%（@3x）
- **注意**：新版 Photoshop 已移除「Save for Web (Legacy)」，建议使用「Export As」或「Quick Export as PNG」功能

### 3. 切片范围：精确还原的关键

#### 操作规范

- **切图框要贴紧元素边缘**，不要留出多余空白

#### 原理说明

- **网页布局是「拼积木」**：前端按像素计算元素位置，如「按钮距离上方 20px」
- **多余空白的影响**：如果按钮本身高 80px，切了 100px 高（上下各留 10px 空白），前端写「距离上方 20px」，实际视觉效果会变成 30px，导致还原度差

#### 例外情况

- **带有弥散投影的元素**：切图框必须包裹住完整投影，否则投影会被「一刀切」切断

## 三、高级切图技巧：提升专业度


### 精灵图
- **原理**：将多个小图标合并到一张大图上，通过 CSS 定位显示不同部分
- **优点**：减少图片体积，提高加载速度
- **适用场景**：大量固定尺寸的小图标、png 动画序列帧


### 小图平铺或拉伸为大图
- **原理**：背景切成连续重复的小图（二方连续、四方连续）平铺，或者小图让开发拉伸成一个大的背景。
- 优点：减少图片体积，提高加载速度



## 四、常见问题与解决方案（QA）

1. **Q：切图边缘有白边怎么办？**  
    **A**：检查导出时背景是否为真透明，并确保使用 PNG-24 格式。
    
2. **Q：导出@2x图在手机上还是模糊？**  
    **A**：首先确认你的设计稿本身是矢量或高分辨率。其次，检查导出倍率设置是否正确。
    
3. **Q：页面图片太多导致加载慢？**  
    **A**：优化方法：① 用WebP格式；② 压缩图片；③ 告知前端可采用“懒加载”（图片进入可视区域再加载）。
