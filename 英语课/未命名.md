# 儿童英语情景演绎互动功能 PRD

## 1. 产品概述
本模块旨在通过“情景演绎”的模式，让儿童在虚拟场景中通过语音与 AI 扮演的角色进行对话，提升英语口语表达能力。界面采用卡通绘本风，通过实时语音识别（ASR）与语音合成（TTS）实现交互。

## 2. 功能配置与核心逻辑

### 2.1 后台配置项
*   **场景背景**：支持上传背景图（PNG/JPG 格式）。
*   **人物组合**：支持选择 2-4 个角色（预置资源库）。
*   **角色定义**：
    *   指定其中 1 个角色为“用户”（头像显示为用户上传的照片）。
    *   指定 AI 角色序列及其对应的话语逻辑。
*   **对话脚本**：配置故事大纲、引导语、过关词库、催促话术。
*   **NPC 位置**：支持自定义各 NPC 在场景中的排列顺序（座位 1-4）。

### 2.2 过关判定规则（逻辑或）
*   **规则 A**：命中词库中 80% 以上的关键词。
*   **规则 B**：交互回复次数达到 N 次。
*   **触发结果**：触发结束语 -> NPC 播放欢呼动画 -> 弹出过关结算 UI。

## 3. 交互逻辑设计

### 3.1 流程控制
1.  **加载阶段**：显示 Loading 动画，完成后进入场景。
2.  **触发阶段**：AI 角色率先发出引导语，触发 AI 角色“说话”动画。
3.  **聆听阶段**：用户语音输入。
    *   按钮状态：显示“待机（点击唤起）” -> “说话（录音中）”。
4.  **响应阶段**：用户说完后，系统判断后由指定 NPC 回复。
5.  **超时处理**：
    *   **催促机制**：若 10 s 内无响应，AI 角色触发催促语。
    *   **跳过机制**：连续 3 次超时未作答，屏幕出现“跳过”按钮。

### 3.2 角色动画状态机
*   **待机（Idle）**：轻微呼吸感/晃动动画。
*   **说话（Speaking）**：嘴部开合动画，配合语音播放。
*   **欢呼（Celebration）**：过关时触发，如跳跃、挥手或表情变大。

## 4. UI 界面规范（基于设计稿）

### 4.1 顶部栏 (Header)
*   **返回按钮**：左侧“X”图标，点击弹出是否退出提示。
*   **进度条**：黄色进度条，展示当前进度。
*   **计数器**：右上角“22/42 已答对 22”，清晰展示任务完成度。

### 4.2 场景内容区 (Main)
*   **对话框 (Bubble)**：
    *   气泡内仅展示图标（表示语音）或根据逻辑优化为无文字纯听力模式（依据产品需求：纯语音，无文字）。
    *   气泡尾巴指向对应的说话角色。
*   **人物层**：
    *   4 个座位（支持动态排列）。
    *   用户头像框：圆角矩形，贴合在“熊玩偶”身体上。

### 4.3 底部交互区 (Interaction)
*   **麦克风按钮**：
    *   **初始态**：圆形背景色+麦克风图标（浅青色）。
    *   **录音态**：中心扩散纹理动画，增强视觉反馈（如图 2）。
    *   **反馈逻辑**：点击或语音唤醒时切换状态。

## 5. 开发排期建议（模块拆解）
1.  **资源加载模块**：优化预加载逻辑，避免场景切换卡顿。
2.  **语音交互引擎**：接入 ASR（识别准确率调优）与 TTS（儿童友好音色）。
3.  **动画组件库**：封装人物状态机（Idle/Speak/Happy）。
4.  **业务逻辑控制器**：处理过关条件计算与超时计时器。

### 设计师/PM 评审建议：
*   **视觉优化建议**：目前 UI 设计稿整体配色清新，建议在“录音中”状态增加更多的呼吸灯特效，给儿童明确的心理暗示——“现在可以说话了”。
*   **交互避坑**：针对“纯语音无文字”的设计，需在前端埋入“音量波动可视化”，即便是没字的环节，也要通过声波反馈告诉用户系统正在听。
*   **扩展性**：虽然目前是固定顺序，建议在后台配置中加入“随机位置”或“轮播位置”开关，增加产品的复玩性。
