## 本文核心要点

本文旨在帮助用户掌握编写安全、好用的自定义 AI Skill（技能）的方法，而非盲目安装第三方 Skill。

## 什么是 Skill？与提示词有何区别？

- **提示词**：管“当前这一次”的特定任务指令。
- **Skill**：管“这一类任务”，是一个包含完整工作流程和规则的“文件夹”（核心是 SKILL.md 文件）。一次写好，AI 识别关键词后自动加载，实现稳定、可复用的输出。
- **何时需要 Skill**：一件事一周内重复 3 次以上，流程基本固定，输出格式可预期。

## 写好 Skill 的核心

1.  **精准的 description**：这是触发 Skill 的关键。需包含具体功能描述和用户的自然触发关键词（例如“做分镜”、“故事转分镜”）。
2.  **清晰的边界**：如果一个 Skill 一句话讲不清楚能干什么，说明边界不清，需要做减法，聚焦主线任务。

## Skill 的基本结构

一个最小可用的 Skill 结构通常只是一个包含 `SKILL.md` 文件的文件夹。复杂一些可以包含以下目录：
```
skill-name/
├── SKILL.md          # 核心文件
├── scripts/          # 辅助脚本
├── references/       # 参考文档
└── assets/           # 素材资源
```

## 构建 Skill 的骨架（多模块框架）

在撰写 `SKILL.md` 正文前，应理清以下 9 个问题，构成 Skill 的逻辑骨架：
1.  目标是什么？
2.  什么情况下触发？
3.  什么情况下不要触发？
4.  开始前先收集什么信息？
5.  按什么顺序干活？
6.  输出必须长什么样？
7.  做到什么程度算完成？
8.  搞不定的时候怎么处理？
9.  什么时候去读参考文件？

## SKILL.md 正文撰写原则

1.  **只写 AI 不知道的东西**：聚焦私有规则、个人习惯、特殊流程。
2.  **流程步骤化并带决策分支**：明确“如果遇到 XX 情况，则...”。
3.  **用示例代替解释**：提供完整的“输入→输出”正反例。
4.  **写任务指令，而非堆砌身份设定**：避免“你是资深专家”这类描述，直接告诉 AI 要做什么。
5.  **信息分层，按需加载**：核心规则放主文件，模板、示例等放参考资料文件，通过引用来调用。
6.  **复杂流程加入验证环节**：在关键步骤后设置检查点。
7.  **先跑起来，再迭代优化**：Skill 很难一次完美，应在使用中持续改进。

### 操作流程示例

文章以创建一个“视频关键帧提取并生成宫格图”的 Skill 为例，展示了该构建器的完整使用过程：
1.  **第一轮（核心意图）**：明确 Skill 产出物、触发词、排除场景和完成标准。
2.  **第二轮（运行环境）**：确定运行平台、可用工具、所需参考资料。
3.  **素材收集**：根据第二轮回答，引导用户上传参考图等配套素材。
4.  **第三轮（输出契约）**：定义输出格式、必含/必避内容、正反例。
5.  **生成与交付**：工具汇总信息，生成完整的 Skill 文件包（含 SKILL.md、文件夹结构、测试 Prompt），并提供下载或写入。

## 总结与清单

- **写好 Skill 的公式**：精准触发 + 清晰流程 + 输出契约 + 可验证标准。
- **安全第一**：自己写的 Skill 最安全、最贴合需求。
- **实践出真知**：从小而具体的 Skill 开始尝试，逐步迭代。
- **验收清单**：
    1.  触发词和排除条件是否已写入 description？
    2.  是否有至少 1 个完整的输入→输出示例？
    3.  SKILL.md 是否不超过 500 行？（过长的内容应拆分为参考资料）
    4.  完成标准的每一条是否都可验证？
    5.  是否实际测试过至少 3 次且均无问题？
