# 编写技能

## 概述

**编写技能即是应用于流程文档的“测试驱动开发 (TDD)”。**

你编写测试用例（针对子代理的压力场景），观察它们失败（基准行为），编写技能（文档），观察测试通过（代理服从），然后重构（堵住漏洞）。

**核心原则：** 如果你没有看到代理在缺乏该技能的情况下失败，你就不确定该技能是否教授了正确的东西。

**必须具备的背景：** 在使用此技能前，你必须理解 superpowers:test-driven-development。

## 什么是技能？

**技能**是关于经过验证的技术、模式或工具的参考指南。技能帮助未来的 Claude 实例找到并应用有效的方法。

**技能是：** 可复用的技术、模式、工具、参考指南。
**技能不是：** 关于你某次如何解决问题的叙述。

## 铁律 (同 TDD)

```
没有先行测试失败，严禁编写或编辑技能。
```

这适用于新技能以及对现有技能的编辑。

## 技能文档结构 (SKILL.md)

**页眉 (YAML)：**
- `name`: 仅使用字母、数字和连字符。
- `description`: 第三人称，**仅**描述何时使用（不要概括它做什么）。以“Use when...”开头。

## 克劳德搜索优化 (CSO)

对于发掘技能至关重要：
1. **丰富的描述字段**：Claude 通过阅读描述来决定加载哪些技能。
2. **关键词覆盖**：使用 Claude 会搜索的词（错误消息、症状、同义词）。
3. **描述性的命名**：动词在前，使用主动语态 (active voice)。

## 信号灯

**写完任何技能后，你必须停止并完成部署流程。**
不要一次批量创建多个技能而不逐一测试。
部署未经测试的技能等同于部署未经测试的代码。
