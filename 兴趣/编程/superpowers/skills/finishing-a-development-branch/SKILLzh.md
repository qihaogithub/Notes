# 结束开发分支

## 概述

通过展示清晰的选项并处理所选的工作流，引导开发工作的完成。

**核心原则：** 验证测试 → 展示选项 → 执行选择 → 清理。

**开始时宣布：** “我正在使用 finishing-a-development-branch 技能来完成这项工作。”

## 流程

### 第 1 步：验证测试

**在展示选项之前，验证测试是否通过：**

```bash
# 运行项目测试套件
npm test / cargo test / pytest / go test ./...
```

**如果测试失败：**
```
测试失败（<N> 个失败）。在完成前必须修复：

[显示失败内容]

在测试通过前，无法进行合并/PR。
```

停止。不要进入第 2 步。

**如果测试通过：** 继续执行第 2 步。

### 第 2 步：确定基准分支 (Base Branch)

```bash
# 尝试常见的基准分支
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

或者询问：“该分支是从 main 分出的 —— 这样对吗？”

### 第 3 步：展示选项

严格展示以下 4 个选项：

```
实施完成。您想做什么？

1. 本地合并回 <base-branch>
2. 推送并创建 Pull Request
3. 保持分支现状（我稍后处理）
4. 丢弃这项工作

选择哪一项？
```

**不要添加解释** —— 保持选项简洁。

### 第 4 步：执行选择

#### 选项 1：本地合并

```bash
# 切换到基准分支
git checkout <base-branch>

# 拉取最新代码
git pull

# 合并功能分支
git merge <feature-branch>

# 在合并结果上验证测试
<test command>

# 如果测试通过
git branch -d <feature-branch>
```

接着：清理工作树（第 5 步）

#### 选项 2：推送并创建 PR

```bash
# 推送分支
git push -u origin <feature-branch>

# 创建 PR
gh pr create --title "<title>" --body "$(cat <<'EOF'
## 摘要
<简述 2-3 点变更内容>

## 测试计划
- [ ] <验证步骤>
EOF
)"
```

接着：清理工作树（第 5 步）

#### 选项 3：保持现状

报告：“保留分支 <name>。工作树保留在 <path>。”

**不要清理工作树。**

#### 选项 4：丢弃

**首先确认：**
```
这将永久删除：
- 分支 <name>
- 所有提交：<commit-list>
- 位于 <path> 的工作树

输入 'discard' 以确认。
```

等待精确的确认。

如果已确认：
```bash
git checkout <base-branch>
git branch -D <feature-branch>
```

接着：清理工作树（第 5 步）

### 第 5 步：清理工作树

**对于选项 1, 2, 4：**

检查是否在工作树中：
```bash
git worktree list | grep $(git branch --show-current)
```

如果是：
```bash
git worktree remove <worktree-path>
```

**对于选项 3：** 保留工作树。

## 快速参考

| 选项 | 合并 | 推送 | 保留工作树 | 清理分支 |
|--------|-------|------|---------------|----------------|
| 1. 本地合并 | ✓ | - | - | ✓ |
| 2. 创建 PR | - | ✓ | ✓ | - |
| 3. 保持现状 | - | - | ✓ | - |
| 4. 丢弃 | - | - | - | ✓ (强制) |

## 常见错误

- **跳过测试验证**：合并损坏的代码。
- **开放式问题**：询问“接下来我该做什么？”。
- **不确认就丢弃**：意外删除工作。

## 信号灯

**绝不：**
- 在测试失败的情况下继续。
- 在未验证合并结果测试的情况下进行合并。
- 未经确认就删除工作。

**始终：**
- 在提供选项前验证测试。
- 只有选项 1 和 4 需要清理工作树。
