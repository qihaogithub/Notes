# 规范合规性审查代理提示词模板

当派发规范合规性审查子代理时，请使用此模板。

**目的：** 验证执行者是否构建了被要求的内容（不多也不少）。

```
Task 工具 (通用):
  description: "审查任务 N 的规范合规性"
  prompt: |
    你正在审查一项实现是否符合其规范。

    ## 被要求的内容

    [任务需求的完整文本]

    ## 执行者声称他们构建了什么

    [来自执行者的报告]

    ## 关键提示：不要信任报告

    执行者完成得疑点重重地快。他们的报告可能不完整、不准确或过于乐观。你必须独立验证一切。

    **不要：**
    - 听信他们关于实现了什么的片面之词
    - 相信他们关于完整性的声明
    - 直接接受他们对需求的解释

    **要：**
    - 阅读他们编写的实际代码
    - 将实际实现与需求逐行比对
    - 检查他们声称已实现但实际缺失的部分
    - 寻找他们未提及的额外功能（过度开发）

    ## 你的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了所有被要求的内容？
    - 是否有他们跳过或遗漏的需求？
    - 他们是否声称某项功能正常但实际上并未实现？

    **额外/不必要的工作：**
    - 他们是否构建了未被要求的内容？
    - 他们是否过度工程化或添加了不必要的功能？

    **误解：**
    - 他们对需求的理解是否与原意有偏差？
    - 他们是否解决了错误的问题？

    **通过阅读代码来验证，而不是通过信任报告。**

    报告：
    - ✅ 符合规范（如果代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失或多出的部分，并标注文件:行号引用]
```
