# 完成前的验证

## 概述

未经验证就宣称工作完成是欺骗，而非效率。

**核心原则：** 声明之前必有证据。

**违反此规则的字面要求即违反了规则的精神。**

## 铁律

```
没有新鲜的验证证据，严禁宣称完成。
```

如果你在当前这条消息中没有运行验证命令，你就不能声称测试通过。

## 门禁函数 (The Gate Function)

在宣称任何状态或表达满意之前：
1. **识别**：什么命令能证明这一声明？
2. **运行**：执行完整的命令（新鲜且完整的执行）。
3. **阅读**：完整输出，检查退出码，清点失败项。
4. **验证**：输出是否证实了声明？
5. **只有这样**：才发出声明。

## 危险信号 —— 停止 (STOP)

- 使用“应该”、“大概”、“似乎”
- 在验证前表达满意（“太棒了！”、“搞定了！”等）
- 打算在没有验证的情况下进行提交/推送/PR
- 相信代理的成功报告
- **任何在运行验证前暗示成功的措辞**

## 底线

**验证没有捷径。** 运行命令。阅读输出。然后声明结果。
这是不可商量的。
