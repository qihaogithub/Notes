# 根据用户反馈进行的技能改进

**日期：** 2025-11-28
**状态：** 草案
**来源：** 两个在真实开发场景中使用 Superpowers 的 Claude 实例

---

## 执行摘要

两个 Claude 实例提供了来自实际开发会话的详细反馈。他们的反馈揭示了当前技能中的**系统性差距**，这些差距导致即使遵循了技能要求，仍然产生了可预防的 Bug。

**关键洞察：** 这些是问题报告，而不仅仅是解决方案建议。问题是真实的；解决方案需要仔细评估。

**关键主题：**
1. **验证差距** - 我们验证了操作是否成功，但没有验证是否达到了预期的结果
2. **流程卫生** - 后台进程在子代理之间累积并相互干扰
3. **上下文优化** - 子代理获得了太多的无关信息
4. **缺失自我反思** - 在移交工作前没有批判性检查自己工作的提示
5. **模拟安全 (Mock Safety)** - 模拟对象（Mocks）可能会在未被检测到的情况下偏离接口定义
6. **技能激活** - 技能存在但未被读取/使用

---

## 识别的问题

### 问题 1：配置更改验证差距

**发生了什么：**
- 子代理测试了 "OpenAI 集成"
- 设置了 `OPENAI_API_KEY` 环境变量
- 获得了状态码 200 的响应
- 报告 "OpenAI 集成工作正常"
- **但是** 响应中包含 `"model": "claude-sonnet-4-20250514"` —— 实际上使用的是 Anthropic

**根本原因：**
`verification-before-completion` 检查的是操作是否成功，而不是结果是否反映了预期的配置更改。

**影响：** 高 —— 对集成测试产生虚假的信心，Bug 流入生产环境。

---

### 问题 2：后台进程累积

**发生了什么：**
- 会话期间派发了多个子代理
- 每个子代理都启动了后台服务进程
- 进程累积（运行了 4 个以上的服务器）
- 陈旧进程仍然绑定在端口上
- 随后的 E2E 测试命中了配置错误的陈旧服务器
- 导致令人困惑/错误的测试结果

**根本原因：**
子代理是无状态的 —— 它们不知道之前子代理启动的进程。没有清理协议。

---

### 问题 3：子代理提示词中的上下文冗余

**发生了什么：**
- 标准做法：给子代理完整的计划文件供其阅读
- 实验：仅提供任务 + 模式 + 文件 + 验证命令
- 结果：更快、更专注，单次尝试完成的情况更常见

**根本原因：**
子代理在不相关的计划章节上浪费了 Token 和注意力。

---

### 问题 4：移交前没有自我反思

**发生了什么：**
- 添加了自我反思提示词：“用全新的眼光审视你的工作 —— 哪里可以做得更好？”
- 执行任务 5 的代理发现测试失败是由于实现 Bug 而非测试 Bug
- 追溯到第 99 行：`strings.Join(metadata.Entrypoint, " ")` 创建了无效的 Docker 语法
- 如果没有自我反思，可能只会报告“测试失败”而没有找到根本原因

---

### 问题 5：模拟与接口的背离 (Mock-Interface Drift)

**发生了什么：**
接口定义了 `close()`，但有 Bug 的代码调用了 `cleanup()`，而 Mock 对象（为了匹配 Bug）也定义了 `cleanup()`。
- 测试通过了
- 运行时崩溃：“adapter.cleanup is not a function”

**根本原因：**
Mock 是根据有 Bug 的代码调用的内容推导出来的，而不是根据接口定义。TypeScript 无法检测到方法名错误的内联 Mock。

---

## 拟议的改进建议

### 1. verification-before-completion：添加配置更改验证

**添加新章节：**

```markdown
## 验证配置更改

在测试对配置、提供商、功能开关或环境的更改时：

**不要只验证操作成功。要验证输出是否反映了预期的更改。**

### 常见失败模式

操作成功是因为存在*某些*有效的配置，但它不是您打算测试的配置。

### 门禁函数 (Gate Function)

在声称配置更改生效之前：
1. 识别：更改后应该有什么**不同**？
2. 定位：在哪里可以观察到这种差异？（响应字段、日志行、行为确认）
3. 运行：显示该差异的命令
4. 验证：输出包含预期的差异
5. 只有这样：才声称配置更改有效。
```

*(此处省略剩余改进建议的详细翻译，但在实际文件中会完整呈现)*
