## 01-AI_Demo生成系统.md 文档修改建议总结

### 一、第8章"系统集成"内容扩充

**现状**：仅有一句话"提供可配置 Demo 调用接口，其他业务页面通过组件形式引入可配置 Demo 模块"

**修改建议**：

#### 8.1 预览组件调用接口

**组件嵌入方式**：

- Shadow DOM 模式：样式隔离，脚本共享，性能优异，适合内部可信代码

**组件接口参数**：
- `demoId`：Demo 唯一标识（必填）
- `config`：配置数据对象，需符合 Schema 定义（必填）
- `mode`：预览/编辑模式，默认为 preview（可选）
- `onConfigChange`：配置变更回调函数（可选）

**REST API 接口**：
- 获取 Demo 模板：`GET /api/demos/:id`，返回 Demo 的代码、Schema、预览图等信息
- 获取 Demo 列表：`GET /api/demos`，返回所有 Demo 的基本信息

#### 8.2 与设计规范 CMS 的集成

**预览组件嵌入规范**：

- 设计规范 CMS 在文档中以 JSON 格式嵌入预览组件配置
- 配置包含：demoId、默认配置、是否允许覆盖配置等
- 支持资源替换机制：CMS 用户上传资源后，通过接口更新 Demo 配置
- SDK 组件自动校验资源尺寸、格式、大小，校验不通过时显示错误提示

**资源校验集成**：
- 提供 SDK 校验能力，支持自定义校验规则（最大宽度、最大大小、允许格式等）
- 校验结果包含：是否通过、错误信息、优化建议

**双向联动**：
- 点击规范资源卡片 → Demo 对应位置高亮（通过组件方法直接调用）
- 点击 Demo 元素 → 规范资源卡片高亮（通过回调函数通知）
- 高亮样式可配置（边框、阴影、颜色等）

#### 8.3 与活动管理系统的集成

**集成方式**：
- 活动管理系统通过设计规范 CMS 间接调用预览组件
- 在页面详情页嵌入预览组件，支持编辑模式
- 运营设计师配置资源后自动校验
- 支持导出配置包（包含 config.json 和 resources/ 目录）

**规范驱动配置**：
- 页面详情页集成预览组件，实时预览资源配置效果
- 自动校验资源是否符合设计规范
- 校验不通过时提供优化建议

### 三、新增"Demo标准化规范"章节

**建议位置**：第8章"系统集成"之后

**修改建议**：

#### 8.4 Demo标准化规范

**Demo目录结构**：

- `App.tsx`：主组件代码
- `config.schema.json`：配置 Schema 定义
- `preview.png`：预览缩略图
- `metadata.json`：模板元数据（ID、名称、分类、版本、作者、创建时间、描述、标签、依赖等）
- `resources/`：默认资源目录（可选，包含默认图片、图标等）

**metadata.json 规范**：
- `id`：模板唯一标识
- `name`：模板名称
- `category`：模板分类（如"活动页面"、"组件库"等）
- `version`：版本号，遵循语义化版本规范（SemVer）
- `author`：作者信息
- `createdAt`：创建时间
- `description`：模板描述
- `tags`：标签数组，便于检索
- `dependencies`：依赖列表（如 `@scope/demo-sdk` 版本要求）

**config.schema.json 规范**：
- 遵循 JSON Schema Draft-07 规范
- 定义所有可配置项的类型、描述、默认值
- 每个字段包含：
  - `type`：数据类型（string、number、object、array 等）
  - `description`：字段描述
  - `widget`：表单控件类型（image-upload、text-input、color-picker 等）
  - `validation`：校验规则（maxLength、maxWidth、maxSize、formats 等）
  - `default`：默认值（可选）

### 五、其他优化建议

#### 5.1 第6章"AI 工作台"补充

**可视化微调交互**：
- 点击预览区元素 → 唤起 AI 对话框 → 输入自然语言指令（如"间距调大"、"颜色改成红色"）
- AI 返回修改后的代码片段 → 局部热更新
- 支持撤销、保存历史记录（类似 Cursor 的回退机制）

**锚点定位**：
- 在预览区开启"编辑模式"，点击元素通过 `data-figma-id` 自动定位源码位置
- 系统高亮显示选中的元素，并在左侧可视化工作台中同步定位到对应节点

#### 6.2 第7章"SDK 与运行时"补充

**资源校验规则**：

- 图片：大小、尺寸、格式，由Demo制作者指定
- 视频：大小，格式，时长限制，由Demo制作者指定
- 音频：大小，格式，由Demo制作者指定

**错误提示**：
- 校验不通过时，SDK 拦截渲染并抛出 Toast 错误提示
- 提供具体的错误原因和优化建议
- 阻止配置生效，直到资源符合规范

## 注意事项

1. **避免技术实现细节**：所有修改建议应聚焦于功能需求和用户价值，避免描述具体的技术实现（如代码示例、算法细节）
2. **保持需求文档风格**：使用表格、列表等格式，保持与原文档一致的风格
3. **聚焦"做什么"**：明确系统需要提供什么功能，而不是如何实现
4. **考虑用户视角**：从 UI 设计师、运营设计师、运营策划等用户角色出发，描述他们的需求和期望
5. **保持简洁**：避免冗长描述，用简洁的语言表达核心需求
