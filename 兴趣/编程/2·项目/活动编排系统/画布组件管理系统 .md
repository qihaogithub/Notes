我们需要引入**“元数据驱动（Metadata-Driven）”**的设计思想，构建一个 **画布组件管理系统 (Canvas Widget System)**。

核心思路是：**不再编写具体的 React 代码来增加新组件，而是通过配置 JSON 来定义组件。**

---

### 1. 系统架构：通用渲染器 + 组件注册表

我们不再为每个组件写 `class TitleShape`、`class PriceShape`。而是只实现一个**通用组件渲染器 (`UniversalWidgetShape`)**。

#### 1.1 核心逻辑
1.  **管理端**：管理员在后台配置组件的样式模板、字段定义（Schema）和默认尺寸。
2.  **存储端**：将这些配置存入数据库的 `widget_registry` 表。
3.  **渲染端 (Tldraw)**：`UniversalWidgetShape` 根据 `widgetType` 读取配置，动态渲染 UI。
4.  **AI 端**：AI 读取注册表，知道当前有哪些“积木”可用，以及如何配置参数。

---

### 2. 数据模型设计 (Schema)

我们需要在数据库中定义一个“画布组件”长什么样。

```typescript
interface WidgetDefinition {
  key: string;          // 组件唯一标识，如 'widget-price-tag'
  name: string;         // 显示名称，如 '价格标签'
  category: string;     // 分类：基础信息 / 数据指标 / 装饰
  
  // 1. 数据协议 (供 AI 和 属性面板 使用)
  propsSchema: {
    fields: [
      { name: 'price', type: 'number', label: '价格', default: 99.9 },
      { name: 'currency', type: 'select', options: ['¥', '$'], default: '¥' },
      { name: 'color', type: 'color', default: '#ff0000' }
    ]
  };

  // 2. 渲染模板 (一种轻量级 DSL 或 预设样式配置)
  // 方案 A: 基于原子样式的配置 (推荐，安全且简单)
  styleConfig: {
    layout: 'flex-row',
    background: 'transparent',
    elements: [
      { type: 'text', value: '{currency}', size: 12, color: '{color}' },
      { type: 'text', value: '{price}', size: 24, weight: 'bold', color: '{color}' }
    ]
  };
  
  // 默认尺寸
  defaultSize: { w: 100, h: 40 };
}
```

### 3. Tldraw 通用渲染器实现

在前端代码中，你只需要注册**一个**自定义 Shape。

```tsx
// UniversalWidgetUtil.tsx
export class UniversalWidgetUtil extends BaseBoxShapeUtil {
  static type = 'universal-widget' // 只有一个类型

  component(shape) {
    const { widgetKey, data } = shape.props;
    
    // 1. 从 Store 或 Context 获取组件定义
    const definition = useWidgetRegistry(widgetKey); 
    
    if (!definition) return <div>Unknown Widget</div>;

    // 2. 根据 definition.styleConfig 动态渲染
    return (
      <HTMLContainer>
        <div className="widget-renderer" style={{ display: 'flex', ... }}>
           {definition.styleConfig.elements.map(el => (
             <span style={{ color: resolveColor(el.color, data) }}>
               {resolveValue(el.value, data)}
             </span>
           ))}
        </div>
      </HTMLContainer>
    )
  }
}
```

### 4. 组件管理后台 (CRUD 系统)

在基础设施层增加一个 **“画布组件库管理”** 模块。

#### 4.1 功能清单
1.  **组件列表**：展示所有已注册的组件卡片，支持按分类筛选（如：电商大促类、日常运营类）。
2.  **可视化编辑器 (No-Code Editor)**：
    *   左侧：字段定义（添加一个文本字段、添加一个颜色选择器）。
    *   中间：预览画布（实时看到 Tldraw 中的渲染效果）。
    *   右侧：样式配置（配置字号、边距、背景色，支持绑定字段变量）。
3.  **版本管理**：修改组件定义后，旧的画布数据是否更新？（通常建议仅影响新生成的组件，或提供“一键升级”功能）。

### 5. AI 与动态组件的联动

这是这套系统最强大的地方。当你新增一个组件后，AI 立即就能学会使用它，无需重新训练模型。

**流程：**

1.  **用户**：新建了一个“倒计时组件 (`widget-countdown`)”，字段有 `endTime`。
2.  **系统**：将所有 `WidgetDefinition` 转换为简化的 **AI Tool Schema**。
    ```json
    // 发给 AI 的提示词上下文
    [
      {
        "tool_name": "add_widget_countdown",
        "description": "添加一个倒计时组件，用于展示活动剩余时间",
        "parameters": { "endTime": "ISO-8601 string" }
      },
      {
        "tool_name": "add_widget_price",
        "description": "添加价格标签",
        ...
      }
    ]
    ```
3.  **AI 行为**：
    *   用户：“生成一个促销卡片，要有倒计时。”
    *   AI 检索工具库，发现有 `widget-countdown`。
    *   AI 生成 JSON：
        ```json
        {
          "type": "universal-widget",
          "props": {
            "widgetKey": "widget-countdown",
            "data": { "endTime": "2024-11-11T00:00:00Z" }
          }
        }
        ```
4.  **结果**：画布上出现了一个倒计时，且完全是动态渲染的。

### 6. 更新架构文档建议

建议在 **02-架构设计.md** 或 **03-首页模块.md** 中，新增 **“画布组件管理子系统”**。

| 模块                        | 职责                                                         |
| :-------------------------- | :----------------------------------------------------------- |
| **Widget Registry Service** | 后端服务。负责组件元数据（Schema、Style）的存储、版本控制。  |
| **Widget Designer**         | 前端界面。低代码编辑器，让开发者/高级运营可视化的创建组件。  |
| **Universal Renderer**      | Tldraw 适配层。一个通用的 ShapeUtil，负责解释元数据并渲染 React DOM。 |
| **AI Protocol Bridge**      | 转换层。将组件元数据实时转换为 AI 可理解的 Function Calling 定义。 |

### 7. 方案总结

通过实现这套 **CRUD 组件管理系统**，你将获得：

1.  **无限扩展性**：新增组件不需要改代码，运营甚至可以自己配一个“红底白字大标题”组件。
2.  **AI 友好性**：组件结构化数据天然适合 AI 理解和调用。
3.  **维护低成本**：前端只需要维护一个 `UniversalWidgetUtil`，几百个组件的逻辑都在数据库配置里。

这是一个典型的 **Low-Code for AI** 的架构思路，非常适合你的项目规模。
