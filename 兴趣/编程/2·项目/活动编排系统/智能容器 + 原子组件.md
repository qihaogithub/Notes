这是一个非常高阶且富有洞察力的需求。你希望打破“卡片=一张死图”的限制，实现**“卡片即画布，组件即积木”**的灵活性。

这完全可行，且是 Tldraw 架构最擅长的领域。我们需要采用 **“复合图形 (Composite Shapes)”** 或 **“父子容器 (Parent-Child Container)”** 的设计模式。

### 1. 核心概念：智能容器 + 原子组件

不再将“活动卡片”视为一个单独的 Shape，而是将其视为一个 **组合（Group/Frame）**，内部包含多个独立的、可编辑的 **子 Shape（Sub-shapes）**。

*   **父容器 (Activity Container)**：负责数据绑定（关联 `PageId`）、整体拖拽、背景样式。
*   **子组件 (Card Widgets)**：预设的积木，如“标题栏”、“缩略图”、“描述文本”、“数据指标”、“状态标签”。

### 2. 用户体验流程

1.  **AI 生成**：用户说“生成一个促销页卡片，要带转化率数据”。AI 会生成一个父容器，并在里面“放置”标题组件、图片组件和数据组件。
2.  **二次编辑**：
    *   用户觉得标题位置不好？直接选中标题组件拖动。
    *   用户想修改描述？直接点击描述组件打字。
    *   用户想删除数据指标？选中数据组件按 Delete 删除。
    *   用户想加个 Tag？从左侧拖入一个“标签组件”丢进卡片里。

### 3. 技术实现方案

在 Tldraw 的数据结构中，这通过 `parentId` 和 `index` 来实现层级关系。

#### 3.1 数据结构设计 (Schema)

我们需要定义一套“卡片组件库”。

**A. 父容器 (Parent Shape)**
```typescript
// type: 'activity-frame'
{
  id: 'shape:frame_001',
  type: 'activity-frame',
  x: 100, y: 100,
  w: 300, h: 400,
  props: {
    pageId: 'p_123', // 核心关联
    backgroundColor: '#f5f5f5'
  }
}
```

**B. 子组件 (Child Shapes)**
这些是独立的 Shape，但 `parentId` 指向父容器。

```typescript
// 1. 标题组件 (type: 'card-title')
{
  id: 'shape:title_001',
  type: 'card-title',
  parentId: 'shape:frame_001', // <--- 关键：绑定到父容器
  x: 20, y: 20, // 这里的坐标是相对于父容器的
  props: { text: '双11主会场', editable: true }
}

// 2. 缩略图组件 (type: 'card-image')
{
  id: 'shape:img_001',
  type: 'card-image',
  parentId: 'shape:frame_001',
  x: 20, y: 60,
  props: { src: 'https://...', w: 260, h: 150 }
}

// 3. 描述组件 (type: 'card-text')
{
  id: 'shape:desc_001',
  type: 'card-text',
  parentId: 'shape:frame_001',
  x: 20, y: 220,
  props: { text: '点击领取优惠券，跳转详情页...' }
}
```

#### 3.2 Tldraw 自定义 Shape 实现

你需要注册这些自定义 Shape。

**父容器 (`activity-frame`) 实现逻辑：**
利用 Tldraw 的 `BaseBoxShapeUtil`，但在渲染时，它主要负责画背景框。
*关键点*：它不需要渲染子元素！Tldraw 引擎会自动根据 `parentId` 将子元素渲染在它上面，并处理随动逻辑（拖拽父容器，子元素跟着动）。

**子组件 (`card-title`) 实现逻辑：**
这就像实现普通的 Tldraw 形状一样。
```tsx
export class CardTitleUtil extends BaseBoxShapeUtil {
  static type = 'card-title'
  
  component(shape) {
    // 支持双击编辑的文本框
    return (
      <HTMLContainer>
        <input 
           value={shape.props.text} 
           onChange={e => updateShape(shape.id, { text: e.target.value })}
           className="font-bold text-lg"
        />
      </HTMLContainer>
    )
  }
}
```

### 4. AI 组装逻辑 (The Assembler)

这是最酷的部分。AI 不再是生成一张图，而是**生成一份构建清单**。

**Prompt 示例：**
> 用户：帮我把“年货节首页”放上去，重点展示它的访问量，不要放缩略图。

**AI Agent 处理流程：**

1.  **意图识别**：需要组件 -> `Frame` + `Title` + `Metrics` (不需要 `Image`)。
2.  **数据检索**：查库获取“年货节首页”的数据 (PV: 10w+)。
3.  **布局计算 (Layout Engine)**：
    *   AI 计算简单的相对坐标 (Relative Layout)。
    *   Title: (0, 0)
    *   Metrics: (0, 50)
4.  **生成 JSON**：
    ```json
    [
      { "id": "frame_1", "type": "activity-frame", "x": 100, "y": 100, ... },
      { "id": "title_1", "type": "card-title", "parentId": "frame_1", "props": { "text": "年货节首页" }, "y": 10 },
      { "id": "metric_1", "type": "card-metric", "parentId": "frame_1", "props": { "value": "PV 10w+" }, "y": 60 }
    ]
    ```
5.  **上图**：前端调用 `editor.createShapes(json)`。

### 5. 优势总结

1.  **极致的灵活性**：
    用户可以把卡片里的“缩略图”放大，或者把“标题”移到卡片底部。完全符合 Tldraw 的白板直觉。
2.  **组件复用**：
    你的 `card-image` 组件可以用在活动卡片里，也可以被用户单独拖出来当做普通图片用。
3.  **数据解耦**：
    如果用户修改了卡片里的标题文字，你可以选择：
    *   **仅修改视图**（只在画布上变，不影响真实页面名称）。
    *   **双向同步**（触发 API 更新数据库中的页面名称）。
4.  **渐进式增强**：
    一开始 AI 可能只生成标准的“标题+图”。随着你喂给 AI 更多的组件定义（如 `card-countdown` 倒计时组件），AI 能生成的卡片样式会越来越丰富。

### 6. 文档补充建议

建议在 `06-项目编排画布.md` 的 **6.3.2 自定义节点** 中，将 **A. 活动页面卡片** 修改为 **A. 复合活动卡片 (Composite Activity Card)**。

**描述更新为：**
> 采用“父子容器”架构。活动卡片并非单一图形，而是由 `activity-frame` 容器和内部的 `card-widgets`（标题、图片、状态、数据）组装而成。
> - **AI 组装**：AI 根据上下文按需挑选组件填入容器。
> - **用户编辑**：用户可选中容器内的任意组件进行独立移动、编辑或删除，实现高度自由的布局调整。

这个方案将你的系统从“查看器”提升到了“编辑器”的维度。
