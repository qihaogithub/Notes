# 项目编排画布系统需求文档 (Project Canvas PRD)

## 1. 系统概述

### 1.1 背景
为了提升活动策划与设计师的协作效率，满足**复杂活动流程编排**、**可视化需求标注**及**低保真原型快速生成**的需求，我们将引入基于 **Tldraw** 的无限画布系统。

### 1.2 核心目标
1.  **可视化编排**：提供无限画布，支持拖拽活动页面、绘制流程连线。
2.  **图文一体化**：在画布中集成富文本编辑器（Tiptap），实现“流程图 + PRD文档”的同屏交付。
3.  **AI 辅助原型**：利用 AI 生成代码 + 布局烘焙技术，实现从自然语言到可编辑 Tldraw 原型的无损转换。
4.  **灵活组件体系**：建立元数据驱动的组件注册表，支持组件的无限扩展与 AI 自动组装。

---

## 2. 总体架构设计

### 2.1 技术栈
- **画布引擎**：[Tldraw](https://tldraw.dev/) (React SDK)
- **文档引擎**：[Tiptap](https://tiptap.dev/) (Headless Editor)
- **AI 布局方案**：HTML/Tailwind -> DOM Layout -> Tldraw Shapes (Layout Baking)
- **组件规范**：Proto-UI (类 Tldraw 风格的 React 组件库)

### 2.2 逻辑架构图

```mermaid

    end
```

## 3. 核心功能模块详细需求

### 3.1 无限画布基础 (Canvas Core)
- **基本操作**：平移、缩放（10% - 400%）、框选、多选、删除、撤销/重做。
- **绘图工具**：手绘笔、橡皮擦、矩形/椭圆/箭头、文本工具。
- **持久化**：画布状态全量 JSON 存储至项目表 `canvas_data` 字段。

### 3.2 资源编排与复合卡片 (Composite Activity Card)
改变传统“一张缩略图”的模式，采用**父子容器架构**。

- **交互流程**：
  1.  用户从左侧“活动库”拖拽一个页面至画布。
  2.  系统根据配置生成一个 `ActivityFrame` (父容器) 和内部的 `Widgets` (子组件)。
- **组件构成**：
  - **父容器 (Frame)**：绑定 `PageID`，处理整体拖拽、背景色。
  - **子组件 (Widgets)**：
    - `TitleWidget`：显示页面名称（支持画布内双向绑定修改）。
    - `StatusWidget`：显示开发状态（待开发/已发布）。
    - `ThumbnailWidget`：页面缩略图。
    - `MetricsWidget`（可选）：显示 PV/UV 数据。
- **操作特性**：
  - **解耦编辑**：用户可单独移动卡片内的“标题”或“图片”，调整布局。
  - **双击跳转**：双击父容器背景，跳转至【页面详情页】进行资源配置。

### 3.3 画布内文档 (Rich Text Documentation)
解决 Tldraw 原生文本编辑体验差的问题，嵌入 Notion 级编辑器。

- **自定义节点**：`rich-doc`。
- **编辑器能力**：
  - 标题 (H1-H3)、无序/有序列表、引用块、链接。
  - 支持 Markdown 快捷语法输入。
- **交互细节**：
  - **事件隔离**：在文档内编辑时，阻止键盘事件冒泡（防止误触 Tldraw 的删除/快捷键）。
  - **拖拽手柄**：顶部设置 Drag Handle，仅按住顶部时可拖拽节点，点击内容区为输入。

### 3.4 AI 原型生成与烘焙 (AI Prototype & Baking)
解决 AI 无法直接绘制完美坐标的痛点。

#### 3.4.1 原理：布局烘焙 (Layout Baking)
1.  **AI 生成代码**：AI 输出基于 Flex/Grid 布局的 HTML 代码（使用 `Proto-UI` 组件库）。
2.  **HTML 容器预览**：Tldraw 中渲染一个 `HTMLContainer`，利用浏览器引擎自动排版。
3.  **烘焙转换**：用户确认后，脚本遍历 DOM 树，计算每个元素的绝对坐标 (`getBoundingClientRect`)，将其替换为对应的 Tldraw 原生 Shape。

#### 3.4.2 流程
1.  **用户指令**：框选区域 -> 输入“生成一个电商大促排行榜，红金配色”。
2.  **系统响应**：
    - 调用 LLM，限制输出为 `<ProtoBox>`, `<ProtoText>` 等组件代码。
    - 画布显示预览组件 (不可内部编辑)。
3.  **转为编辑**：
    - 用户点击“转为可编辑”。
    - **系统执行烘焙算法**：HTML -> Native Shapes。
    - 结果：一组可独立选中的矩形、文字和图片占位符。

## 4. 基础设施支撑

### 4.1 组件注册中心 (Widget Registry)
为了支持 `3.2` 中的复合卡片和组件的灵活扩展，建立元数据驱动的组件库。

**数据模型 (Schema):**
```json
{
  "widgetKey": "widget-countdown",
  "name": "倒计时组件",
  "category": "营销",
  "propsSchema": {
    "endTime": { "type": "datetime", "label": "结束时间" },
    "style": { "type": "select", "options": ["dark", "light"] }
  },
  "defaultSize": { "w": 200, "h": 60 },
  "reactComponent": "CountdownWidget" // 映射前端通用渲染器
}
```

### 4.2 Proto-UI 组件库 (用于 AI 生成)
一套专为 AI 生成设计的 React 组件库，样式模仿 Tldraw 手绘风格。
- `ProtoBox`：对应 `geo-rectangle`。
- `ProtoButton`：对应 `geo-rectangle` + `text`。
- `ProtoImage`：对应 `image` 占位符。
- **特性**：包含 `data-proto-type` 属性，用于烘焙阶段的类型映射。

## 5. 用户使用流程 (User Story)

### 场景一：活动策划
1.  **创建项目**：新建“双11大促项目”，进入画布页。
2.  **流程绘制**：从左侧拖入“主会场”、“分会场”页面卡片。使用连线工具连接，标记跳转逻辑。
3.  **需求撰写**：在“主会场”卡片旁添加 `rich-doc` 节点，撰写详细的埋点需求和活动规则。

### 场景二：原型创作 (AI 辅助)
1.  **提出需求**：在画布空白处输入“生成一个抽奖弹窗原型，包含轮盘、剩余次数和关闭按钮”。
2.  **预览确认**：系统生成预览组件，用户查看布局是否合理。
3.  **烘焙编辑**：点击“确认”，预览组件炸开变为独立的 Tldraw 图形。
4.  **手动微调**：用户手动微调“关闭按钮”的位置，将其保存为项目资产。

## 6. 非功能性需求

1.  **性能**：画布支持 1000+ 节点流畅渲染（利用 Tldraw 的视口剔除机制）。
2.  **兼容性**：
    - 仅支持 PC 端操作（鼠标/触控板）。
    - 移动端仅支持只读预览模式。
3.  **数据一致性**：多人协作时（如未来扩展），需处理并发冲突（推荐基于 Yjs 的 CRDT 方案，Tldraw 原生支持）。
