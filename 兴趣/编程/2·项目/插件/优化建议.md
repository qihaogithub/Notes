renderers.ts代码从**性能（Figma 插件运行速度）**、**代码可维护性**和**健壮性**的角度来看，还有不少优化空间。以下是针对该文件的详细优化建议：

### 1. 性能优化 (关键)

#### A. 移除或限制 `console.log` (最重要)
**问题**：代码中包含大量的 `console.log`（特别是在 `renderTable`、`renderTableRow` 和 `renderImage` 的循环中）。
**影响**：Figma 插件的 `console.log` 需要将对象序列化并在 UI 线程和沙箱线程之间传递。在渲染大量表格或长文档时，这会**显著**降低渲染速度（可能慢 10 倍以上）。
**建议**：
*   删除生产环境不需要的日志。
*   或者封装一个 `Logger` 类，通过一个全局开关 `const DEBUG = false` 来控制。

#### B. 优化正则表达式
**问题**：在 `calculateTextWidth` 函数中，正则表达式 `/[\u4e00-\u9fa5]/` 和 `/[a-zA-Z]/` 是在循环内部定义的。
**影响**：虽然 JS 引擎有优化，但在高频调用的循环（计算每个单元格宽度）中，最好将其提升到模块作用域。
**建议**：
```typescript
// 移到文件顶部
const CHINESE_CHAR_REGEX = /[\u4e00-\u9fa5]/;
const LATIN_CHAR_REGEX = /[a-zA-Z]/;

function calculateTextWidth(...) {
  // ... 使用常量正则
}
```

#### C. 字体加载优化
**问题**：`processInlineFormats` 中，对于每一个 text span 都可能调用 `await globalFontCache.loadFont(...)`。
**影响**：如果是串行 `await`，会导致严重的“瀑布流”延迟。
**建议**：虽然 `globalFontCache` 应该有缓存，但建议在处理一个段落前，先分析出所有需要的字体（Regular, Bold, Italic, Mono），**并行 (`Promise.all`)** 加载一次，然后再进行样式应用。

### 2. 代码结构与复用 (DRY)

#### A. 封装 AutoLayout Frame 创建工厂
**问题**：几乎每个 `render...` 函数都在手动创建 Frame、设置 `layoutMode`、`layoutAlign`、`sizingMode` 等重复代码。
**建议**：创建一个辅助函数来减少样板代码。

```typescript
interface FrameOptions {
  layoutMode: "VERTICAL" | "HORIZONTAL";
  spacing?: number;
  padding?: number | { top: number; right: number; bottom: number; left: number };
  fill?: Variable | string | RGB; // 简化颜色传入
  radius?: number;
  // 专门处理布局策略
  layoutAlign?: "STRETCH" | "MIN" | "MAX" | "CENTER" | "INHERIT";
  primaryAxisSizingMode?: "FIXED" | "AUTO";
  counterAxisSizingMode?: "FIXED" | "AUTO";
  width?: number; // 如果是 Fixed 需要传
}

function createAutoLayoutFrame(options: FrameOptions): FrameNode {
  const frame = figma.createFrame();
  frame.layoutMode = options.layoutMode;
  frame.itemSpacing = options.spacing || 0;
  
  // 布局策略统一处理
  frame.layoutAlign = options.layoutAlign || "STRETCH";
  frame.primaryAxisSizingMode = options.primaryAxisSizingMode || "AUTO";
  frame.counterAxisSizingMode = options.counterAxisSizingMode || "AUTO";

  // ... padding 和 color 的处理 ...
  return frame;
}
```
这样 `renderBlockquote` 等函数可以缩减一半行数。

### 3. 具体逻辑优化

#### A. `renderImage` 的 Base64 解码
**问题**：代码中手动实现了一个 Base64 解码器和 `atob` polyfill。
**建议**：Figma 现在的 API 环境（QuickJS）通常支持 `figma.base64Decode`。即使需要 fallback，手动位移操作也比较晦涩。
**优化**：
1.  优先使用 `figma.base64Decode(base64String)`（直接返回 Uint8Array）。
2.  只有当该 API 不存在时才使用 fallback。

#### B. `renderText` 中的布局属性设置时机
**问题**：代码注释写着 `layoutSizingHorizontal` 必须在添加到父容器后设置，但在 `renderText` 的 `codeBlock` 分支中又设置了 `codeFrame.layoutAlign = "STRETCH"`。
**建议**：`layoutAlign` (Align Self) 是可以在添加到父级之前设置的，**不能设置的是** `layoutSizingHorizontal/Vertical` (Fill container)。
代码中目前混合使用了 `layoutAlign` 和后续在 adapter 中设置 sizing，逻辑略显分散。建议：**凡是 `layoutAlign` 都在 render 阶段设置好，凡是 `layoutSizing` (Fill/Hug) 尽量也在 render 阶段设置（如果父级不是动态生成的），或者统一留给 adapter。**

#### C. `calculateTextWidth` 的计算逻辑
**问题**：当前的宽度计算是基于字符类型的简单估算 (`fontSize * 0.6` 等)。这对于非等宽字体（Inter）来说误差很大。
**建议**：虽然在插件端无法获取精确渲染宽度，但可以考虑引入稍微精确一点的权重表（例如 `i`, `l` 很窄，`m`, `w` 很宽）。或者，如果允许异步，可以创建一个临时的不可见 TextNode，设置好内容后读取其 `width`，然后删除。**这才是最精确的方法**。
*注意：创建临时节点会有性能开销，仅建议在表格渲染等对宽度敏感的场景使用，或者只计算一次。*

### 优化后的代码片段示例

以下是应用了部分优化（主要是**去日志**、**工厂函数**和**正则优化**）后的修改建议：

```typescript
// --- 顶部常量 ---
const CHINESE_CHAR_REGEX = /[\u4e00-\u9fa5]/;
const LATIN_CHAR_REGEX = /[a-zA-Z]/;
// 控制日志开关
const DEBUG_MODE = false;
function log(msg: string, ...args: any[]) {
  if (DEBUG_MODE) console.log(msg, ...args);
}

// --- 辅助工厂函数 ---
function createLayoutContainer(options: {
  mode: "VERTICAL" | "HORIZONTAL";
  spacing?: number;
  padding?: number | { t: number; r: number; b: number; l: number };
  fill?: RGB;
  stroke?: { color: RGB; weight?: number; side?: 'ALL' | 'LEFT' | 'BOTTOM' };
  radius?: number;
  layoutAlign?: "STRETCH" | "MIN";
}): FrameNode {
  const frame = figma.createFrame();
  frame.layoutMode = options.mode;
  frame.itemSpacing = options.spacing || 0;
  frame.layoutAlign = options.layoutAlign || "STRETCH"; // 默认填满
  
  // 默认均为自适应，特殊情况外部覆盖
  frame.primaryAxisSizingMode = "AUTO"; 
  frame.counterAxisSizingMode = "AUTO";

  if (options.padding) {
    if (typeof options.padding === 'number') {
      frame.paddingLeft = frame.paddingRight = frame.paddingTop = frame.paddingBottom = options.padding;
    } else {
      frame.paddingTop = options.padding.t;
      frame.paddingRight = options.padding.r;
      frame.paddingBottom = options.padding.b;
      frame.paddingLeft = options.padding.l;
    }
  }

  if (options.fill) frame.fills = [{ type: "SOLID", color: options.fill }];
  if (options.radius) frame.cornerRadius = options.radius;
  
  // 简化的描边处理
  if (options.stroke) {
    frame.strokes = [{ type: "SOLID", color: options.stroke.color }];
    if (options.stroke.side === 'LEFT') {
      frame.strokeLeftWeight = options.stroke.weight || 1;
      frame.strokeTopWeight = frame.strokeRightWeight = frame.strokeBottomWeight = 0;
    } else {
      frame.strokeWeight = options.stroke.weight || 1;
    }
  }

  return frame;
}

// --- 优化后的 renderBlockquote ---
export async function renderBlockquote(node: any): Promise<FrameNode> {
  // 使用工厂函数减少样板代码
  const quoteFrame = createLayoutContainer({
    mode: "VERTICAL",
    spacing: 8,
    padding: { 
      t: 8, b: 8, r: 16, 
      l: 16 + (node.attrs?.depth || 0) * 10 // 动态计算
    },
    fill: { r: 0.96, g: 0.96, b: 0.96 },
    stroke: { color: { r: 0.8, g: 0.8, b: 0.8 }, weight: 4, side: 'LEFT' },
    radius: 4
  });

  // 显式设置约束（工厂函数未处理）
  quoteFrame.constraints = { horizontal: "STRETCH", vertical: "MIN" };

  // 递归渲染子节点
  if (node.children && Array.isArray(node.children)) {
    // 建议：收集所有 Promise 并行执行（除非顺序非常严格且有副作用，renderNode 通常是安全的）
    // 但为了保持添加到 Frame 的顺序，串行 await 是最稳妥的，或者 Promise.all 后按顺序 append
    for (const child of node.children) {
      const childNode = await renderNode(child);
      if (childNode) quoteFrame.appendChild(childNode);
    }
  } else if (node.content && typeof node.content === "string") {
    const textNode = figma.createText();
    await globalFontCache.loadFont({ family: "Inter", style: "Regular" });
    textNode.fontName = { family: "Inter", style: "Regular" };
    textNode.characters = node.content;
    quoteFrame.appendChild(textNode);
  }

  return quoteFrame;
}

// --- 优化后的 calculateTextWidth ---
function calculateTextWidth(text: string, fontSize: number = 14): number {
  if (!text || text.trim() === '') return 80;
  
  const lines = text.split('\n');
  let maxLineWidth = 0;
  
  for (const line of lines) {
    if (line.trim() === '') continue;
    let lineWidth = 0;
    for (const char of line) {
      // 使用顶部定义的常量正则
      const charWidth = CHINESE_CHAR_REGEX.test(char) ? fontSize * 1.0 : 
                       LATIN_CHAR_REGEX.test(char) ? fontSize * 0.6 : fontSize * 0.5;
      lineWidth += charWidth;
    }
    if (lineWidth > maxLineWidth) maxLineWidth = lineWidth;
  }
  
  // Math.min/max 逻辑保持不变
  const totalWidth = Math.ceil(maxLineWidth + 16);
  return Math.min(Math.max(totalWidth, 80), 400);
}

// --- 优化后的 renderImage (简化 Base64) ---
export async function renderImage(node: any): Promise<RectangleNode> {
  log("[renderImage] 开始渲染:", node.attrs?.alt); // 使用封装的 log

  const imageRect = figma.createRectangle();
  imageRect.constrainProportions = true;
  imageRect.layoutAlign = "STRETCH";
  imageRect.layoutGrow = 0;
  
  const src = node.attrs?.src || "";
  
  if (!src) {
     // ... 错误处理保持不变 ...
     return imageRect;
  }

  try {
    let image: Image;

    if (src.startsWith("data:image/")) {
      const base64Data = src.split(",")[1];
      // 直接使用 Figma API
      const imageBytes = figma.base64Decode(base64Data); 
      image = figma.createImage(imageBytes);
    } else {
      image = await figma.createImageAsync(src);
    }

    // 获取尺寸并 resize
    const { width, height } = await image.getSizeAsync();
    
    // ... 尺寸限制逻辑保持不变 ...
    const finalWidth = node.attrs?.width || width;
    const finalHeight = node.attrs?.height || height;
    
    imageRect.resize(finalWidth, finalHeight);
    imageRect.fills = [{ type: "IMAGE", imageHash: image.hash, scaleMode: "FIT" }];

  } catch (error) {
    console.error("图片渲染失败", error); // 错误日志保留
    // ... 错误样式填充 ...
  }
  return imageRect;
}
```

### 总结建议

1.  **立刻执行**：搜索全文 `console.log`，除了 catch 块中的 `console.error`，其他的建议全部注释掉或加上 `if (DEBUG)` 判断。这对性能提升最明显。
2.  **立刻执行**：将正则变量提取到函数外部。
3.  **建议重构**：引入 `createLayoutContainer` 工厂函数，清理 `renderBlockquote`、`renderCodeBlock`、`renderMathBlock` 中的重复代码，这会让文件体积减小并易于统一修改样式。
4.  **稳健性**：在 `renderImage` 中改用 `figma.base64Decode`，删除那个冗长的手动解码逻辑。
