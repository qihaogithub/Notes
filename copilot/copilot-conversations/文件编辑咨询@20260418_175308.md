## 三、核心交互与状态流转逻辑

### 3.1 订单生命周期管理
- **取号/订座/就餐关系**：三者应视为同一订单的生命周期状态，而非独立订单类型。用餐完成后，取号记录自动归档至「历史记录」，主列表仅保留活跃态订单。
- **列表过滤策略**：订单页默认展示 `待确认`、`已确认`、`就餐中` 状态；`已满座`、`已取消`、`已过号` 等终态订单折叠至「历史订单」Tab 或详情页底部。

### 3.2 二级操作引导（Next Action）
不同订单状态需匹配明确的下一步引导，避免用户迷失：
- `已取号` → 开启排队提醒 / 查看当前叫号进度
- `已过号` → 一键重新取号 / 联系客服
- `已订座` → 提前点菜 / 导航前往门店
- `已取消` → 重新预定 / 查看取消原因
- `就餐中` → 呼叫服务员 / 加菜 / 申请结账
- `已完成` → 开发票 / 评价订单

> 💡 **决策建议**：上述交互需在本期统一输出状态机图与按钮显隐规则，确保开发一次性覆盖异常分支。
