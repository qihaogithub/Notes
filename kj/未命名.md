本页面整理基于烤匠防黄牛重复取号验证方案，覆盖C端小程序全流程所有页面，每个页面明确**核心功能**、**UI设计要点**、**交互逻辑**、**异常/特殊处理**，贴合微信小程序原生设计规范，兼顾验证流程的简洁性和操作指引的清晰性，指导UI完成页面视觉与交互设计。

整体设计原则：流程轻量化，减少用户手动操作；验证进度可视化，错误提示明确易懂；关键操作（如扫码、填写）突出引导，非核心信息弱化展示；适配微信小程序不同设备屏幕，保证操作便捷性。

## 扫码进入页面
### 核心功能
扫描门店专属小程序码后进入的首页面，解析小程序码的scene参数提取门店ID，完成门店自动匹配，为后续验证流程做基础准备。
### UI设计要点
1. 页面以轻量加载为核心，主视觉区域展示烤匠品牌logo+简约加载动效（如排队图标、加载转圈）；
2. 下方搭配简洁文案，如「正在识别门店信息，请稍候」；
3. 页面底部预留**客服入口**（小图标+文字「遇到问题？联系客服」），置于固定位置；
4. 整体配色贴合烤匠品牌视觉，避免冗余元素，保证加载过程的视觉简洁性。
### 交互逻辑
1. 用户扫码后自动跳转至该页面，无需手动操作，系统后台自动解析scene参数；
2. 解析成功后，无感知跳转到**验证流程页面**，无额外确认步骤；
3. 解析过程设置**加载超时阈值**（建议2秒），超时后触发异常提示。
### 异常/特殊处理
1. scene参数缺失/格式错误：页面停止加载，展示异常提示文案+重新扫码按钮，按钮点击后调起微信小程序扫码功能；
2. 门店ID无效：展示「门店信息错误，请重新扫描门店小程序码」+扫码按钮；
3. 网络异常：展示「网络不佳，无法识别门店信息」+刷新按钮，点击刷新重新解析参数。

## 验证流程页面
### 核心功能
执行全流程核心验证操作，依次完成**数美风控数据采集**、**GPS定位验证**、**Union ID校验**、**手机号验证/关联**、**数美风控判断**、**重复取号检测**，是取号的核心验证环节。
### UI设计要点
1. 页面左侧/顶部做**验证步骤可视化**设计（无需手动操作，仅展示进度），如「定位验证→身份校验→重复取号检测」，当前验证步骤标红/高亮，已完成步骤打勾，未开始步骤置灰；
2. 主区域展示**当前验证状态**，如「正在验证您的位置信息」「正在校验手机号」，搭配对应轻量动效（如定位图标、手机图标微动）；
3. 页面底部保留固定客服入口，无其他可操作按钮，避免用户误操作；
4. 验证成功后展示**成功提示动效**（如对勾），快速跳转至下一页。
### 交互逻辑
1. 所有验证操作**后台自动执行**，无需用户手动触发，按「GPS定位验证→Union ID校验→手机号处理→风控判断→重复取号检测」的固定顺序执行；
2. 每一步验证完成后，步骤栏实时更新进度，无感知进入下一步；
3. 全部验证通过后，自动跳转到**用餐人数填写页面**；
4. 任意一步验证失败，立即停止流程，展示对应异常提示，跳转/停留在本页面并提供解决方案。
### 异常/特殊处理
| 验证失败类型 | 展示文案 | 处理方式 |
|--------------|----------|----------|
| GPS定位获取失败 | 无法获取位置信息，请检查位置权限 | 搭配「去设置」按钮，点击跳转到微信小程序位置权限设置页 |
| GPS定位不在门店附近 | 您不在门店附近，请到门店现场进行验证 | 仅展示文案，无操作按钮，引导用户到店 |
| Union ID获取失败 | 无法获取用户信息，请重新打开小程序 | 搭配「重新打开」按钮，点击刷新小程序 |
| 手机号获取失败 | 无法获取手机号，请检查微信授权 | 搭配「去授权」按钮，点击调起微信手机号授权弹窗 |
| 用户拒绝授权（定位/手机号） | 需要授权位置和手机号才能进行验证，请重新授权 | 搭配「重新授权」按钮，点击重新调起授权弹窗 |
| 数美风控验证失败 | 风险验证失败，不允许取号 | 仅展示文案，无具体原因，避免被黄牛绕过 |
| 数美风控服务异常 | 验证服务异常，请稍后重试 | 搭配「重新验证」按钮，点击重新执行全流程验证 |
| 重复取号检测失败 | 您已在X时X分取号，请勿重复取号<br>（附已取号信息：排队号/取号时间） | 搭配「联系门店」按钮，点击跳转至门店客服/电话页面 |

## 用餐人数填写页面
### 核心功能
验证全通过后，供用户填写实际用餐人数，提交后生成取号申请，进入门店确认环节。
### UI设计要点
1. 页面顶部展示**验证通过提示**，如「验证通过，请填写用餐人数」，搭配对勾图标；
2. 主区域为**用餐人数选择/输入框**，核心突出，支持**数字选择器（滚轮式）+手动输入**双模式，默认显示1人；
3. 明确标注用餐人数范围：「请填写1-20人」，超出范围的数字做红色标红提示；
4. 页面底部设置**大尺寸提交按钮**（如「提交取号申请」），按钮置底固定，配色为品牌主色，未填写/填写无效时按钮置灰不可点击；
5. 其余区域简洁设计，无冗余元素，保证操作聚焦。
### 交互逻辑
1. 用户可通过滚轮选择或手动输入用餐人数，输入框实时做数字验证，非数字/超出1-20范围时实时提示；
2. 填写有效人数后，提交按钮由灰变亮，可点击；
3. 点击提交后，后台将手机号、用餐人数、Union ID、UUID等信息存储到数据库，状态标记为「待门店确认」；
4. 提交成功后，自动跳转到**等待确认页面**，并展示短暂的「提交成功」提示。
### 异常/特殊处理
1. 用餐人数为空/0/大于20：输入框下方展示红色提示「用餐人数必须在1-20人之间」，提交按钮置灰；
2. 提交时网络异常：展示「网络异常，提交失败」+「重新提交」按钮，点击重新提交申请；
3. 提交时后台存储失败：展示「取号申请提交失败，请联系门店」+客服入口。

## 等待确认页面
### 核心功能
展示取号申请的待确认状态，根据门店配置的**手动确认**/**动态二维码自动确认**模式，展示不同的引导文案和操作入口，等待门店完成确认。
### UI设计要点
1. 页面顶部统一展示**待确认状态标题**，如「取号申请已提交，等待确认」，搭配「待确认」状态标签（浅黄/橙色）；
2. 主区域展示**取号申请信息**，包括「申请时间：XXXX-XX-XX XX:XX」「用餐人数：X人」，信息居中展示，排版清晰；
3. 区分两种确认模式做差异化设计，核心操作按钮/入口突出展示；
4. 页面底部保留固定客服入口，搭配温馨提示「请耐心等待，确认后将为您展示排队号」。
#### 手动确认模式专属设计
- 核心文案：「门店工作人员正在为您确认，请等待现场伙伴核实」；
- 无额外操作按钮，仅展示等待引导，弱化其他视觉元素。
#### 动态二维码自动确认模式专属设计
- 核心文案：「请扫描门店动态二维码完成现场确认」；
- 主区域设置**大尺寸扫码按钮/扫码入口**（如「点击扫码确认」），按钮搭配二维码图标，支持点击调起微信小程序扫码功能；
- 扫码入口旁标注提示「请扫描门店现场的动态二维码，二维码5分钟刷新一次」。
### 交互逻辑
1. 页面加载后，后台自动识别门店确认模式，展示对应页面内容；
2. 手动确认模式：页面实时监听门店确认状态，确认成功后自动跳转到**取号成功页面**；
3. 动态二维码自动确认模式：用户点击扫码入口，调起小程序扫码功能，扫描门店动态二维码后，后台自动验证二维码有效性，验证通过则完成确认，跳转到**取号成功页面**；
4. 页面设置**状态刷新机制**（每30秒自动刷新），无需用户手动操作。
### 异常/特殊处理
1. 动态二维码扫描失败（无效/过期/已使用）：展示「二维码无效，请重新扫描门店最新动态二维码」，返回本页面，扫码入口可再次点击；
2. 二维码验证时手机号在黑名单：展示「取号申请未通过，请联系门店」，不显示具体原因；
3. 门店确认超时（建议设置10分钟阈值）：展示「取号申请确认超时，是否重新提交」，搭配「重新提交」按钮，点击回到用餐人数填写页面。

## 动态二维码扫描页面（仅动态二维码自动确认模式）
### 核心功能
作为动态二维码自动确认模式的专属扫码页面，调起微信小程序扫码功能，完成门店动态二维码的扫描和验证，是衔接取号申请和确认成功的中间页面。
### UI设计要点
1. 页面主体为**微信原生扫码取景框**，占满页面80%以上区域，取景框内标注提示「请对准门店动态二维码扫码」；
2. 取景框下方搭配**操作提示文案**，如「轻触屏幕可放大/缩小，取消可返回上一页」；
3. 页面左上角设置**返回按钮**，点击可回到等待确认页面；
4. 无其他冗余元素，保证扫码操作的聚焦性，适配不同手机的扫码取景比例。
### 交互逻辑
1. 从等待确认页面点击扫码入口后，无感知跳转到本页面，自动调起扫码功能，无需用户额外触发；
2. 扫码成功后，后台自动解析二维码信息，验证门店ID、有效期、token等；
3. 验证通过则完成门店确认，后台调用美团排号接口获取排队号，自动跳转到**取号成功页面**；
4. 验证失败则展示对应异常提示，返回本页面或等待确认页面。
### 异常/特殊处理
1. 扫码超时（微信原生超时，约10秒）：展示「扫码超时，请重新尝试」+「重新扫码」按钮，点击重新调起扫码功能；
2. 二维码信息与门店不匹配：展示「二维码与当前门店不符，请扫描对应门店动态二维码」+返回按钮；
3. 二维码已过期/已使用：展示「二维码已失效，请联系门店刷新后重新扫描」+返回按钮。

## 取号成功页面
### 核心功能
门店确认完成后，展示取号成功状态，同步展示美团排号系统返回的排队号及基础排号信息，是取号流程的关键成功节点。
### UI设计要点
1. 页面顶部展示**取号成功强提示**，如「取号成功！」，搭配大尺寸对勾动效+品牌喜庆配色（如红色/橙色），强化视觉反馈；
2. 主区域做**排队核心信息卡片设计**，卡片化展示关键信息，包括「排队号：X00X」「用餐人数：X人」「前面还有X桌」「预计等待时间：X分钟」，信息字号由大到小，排队号为最大字号，突出展示；
3. 信息卡片下方设置**查看排号进度**按钮，按钮为品牌主色，点击跳转到**排队号展示页面**；
4. 页面底部展示温馨提示，如「请留意叫号通知，快轮到您时我们会提醒您」，并保留客服入口；
5. 页面支持**一键截图**提示（如「点击截图保存排队号」），方便用户留存。
### 交互逻辑
1. 门店确认/二维码验证通过后，后台调用美团排号接口获取排队号，关联用户信息后，自动跳转到本页面；
2. 页面加载完成后，自动播放短暂的成功动效（如对勾弹出、数字跳动）；
3. 点击「查看排号进度」按钮，立即跳转到排队号展示页面，实时查看排号动态；
4. 无操作情况下，停留5秒后自动跳转到排队号展示页面。
### 异常/特殊处理
1. 美团排号接口调用失败，未获取到排队号：展示「排队号获取失败，请联系门店工作人员」+「联系门店」按钮+客服入口；
2. 排队号信息加载不全：展示「排号信息加载中，请稍候」+刷新按钮，点击刷新重新获取信息。

## 排队号展示页面
### 核心功能
展示排队号全量信息，实时更新排号进度，支持自动刷新，通过UUID和Union ID匹配验证防止黄牛卖号，是用户等待期间的核心查看页面。
### UI设计要点
1. 页面顶部做**固定导航栏**，展示「我的排队号」+当前排队状态标签（如「排队中」「即将叫号」「已叫号」），状态标签按不同状态配色（排队中-蓝色、即将叫号-橙色、已叫号-绿色、已过号-红色）；
2. 主区域为**排队信息固定展示区**，卡片化展示「排队号、用餐人数、取号时间、门店名称」，信息永久展示，不随刷新变化；
3. 下方为**实时排号进度区**，展示「当前叫号：X00X」「前面还有X桌」「预计等待时间：X分钟」，进度区做**刷新动效**（刷新时轻微闪烁/加载），更新后数字标红提示1秒；
4. 页面设置**即将叫号提醒模块**（如「您的排队号即将叫号，请做好准备」），当前面剩余桌数≤3时，模块高亮闪烁，强化提醒；
5. 页面底部设置**功能按钮区**，包括「刷新进度」（手动刷新）、「联系门店」、「取消排队」，按钮按重要性排序，取消排队按钮做二次确认提示；
6. 全页面适配小程序后台自动刷新，刷新时无感知，不影响用户查看。
### 交互逻辑
1. 从取号成功页面跳转/自动进入本页面后，后台立即通过**UUID+Union ID**匹配验证，验证通过后展示排号信息；
2. 页面设置**自动刷新机制**：每5分钟自动刷新一次，每次刷新前均执行UUID+Union ID匹配验证，验证通过则更新排号进度，验证失败则触发异常处理；
3. 用户可点击「刷新进度」按钮手动刷新，手动刷新同样执行匹配验证；
4. 点击「取消排队」按钮，调起二次确认弹窗（如「确定取消排队吗？取消后将无法恢复」），确认后后台更新排队状态为「已取消」，并同步到美团排号系统；
5. 排号状态发生变化（如已叫号、已过号、已入座）时，页面实时更新状态标签和文案，并有消息提示（微信小程序原生模板消息）。
### 异常/特殊处理
1. UUID和Union ID不匹配：展示「身份验证已过期，请重新验证手机号」+「重新验证」按钮，点击后跳转到**验证流程页面**，重新完成全流程验证；
2. 排号进度查询失败：展示「排号进度更新异常，请稍后刷新」+「手动刷新」按钮，点击重新获取进度；
3. 已过号：状态标签标红为「已过号」，展示文案「您的排队号已过号，请联系门店确认是否可重新排号」+「联系门店」按钮；
4. 排队号被取消（门店/用户）：状态标签为「已取消」，展示取消时间，无其他操作按钮。

## 异常提示页面
### 核心功能
作为全流程的**通用异常兜底页面**，处理所有未在各环节单独定义的异常场景（如系统异常、接口调用失败、数据一致性异常等），统一展示异常提示并提供解决方案。
### UI设计要点
1. 页面主视觉为**通用异常图标**（如感叹号），搭配品牌浅灰色调，避免视觉压抑；
2. 主区域展示**统一异常标题**+**个性化异常文案**，标题如「操作失败」，文案根据具体异常场景定制；
3. 文案下方搭配**核心解决方案按钮**（如「重新尝试」「联系客服」「返回首页」），按钮为品牌主色，数量不超过2个，避免用户选择困难；
4. 页面底部展示**异常说明小字**，如「如问题持续，请联系烤匠官方客服：XXX-XXXXXXX」；
5. 整体设计简洁，无冗余元素，聚焦解决问题。
### 交互逻辑
1. 全流程任意环节触发未定义的异常时，均跳转到本页面，后台传递异常类型，页面展示对应文案和解决方案；
2. 点击「重新尝试」按钮，返回异常触发的上一页面，重新执行上一步操作；
3. 点击「返回首页」按钮，回到小程序首页/扫码进入页面，可重新扫码开始流程；
4. 点击「联系客服」按钮，跳转至微信客服/门店电话/在线咨询页面。
### 覆盖异常场景
1. 系统通用异常：如后台服务崩溃、数据库连接失败；
2. 美团排号系统同步异常：如排号信息归零失败、同步等位信息连续失败；
3. 接口调用通用失败：如超时、限流、鉴权失败；
4. 数据一致性异常：如用户信息与排号信息不匹配；
5. 其他未单独定义的异常：如小程序版本过低、设备不兼容等。
